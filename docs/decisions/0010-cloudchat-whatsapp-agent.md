# 0010 WhatsApp AI agent (Max on CloudChat): CRM side

**Context (Sahar, 24/10/2026):** Max, TRAX's WhatsApp agent, runs on Vitrue's agent platform over CloudChat (UChat white label, workspace "TRAX Club" 326381, bot flow f296163). The CRM must start the conversation for every new sale, let the user opt out per customer/sale at creation, show the conversation read-only on the customer and sale screens, and track who got a message and who answered.

**Decision:**
1. **DB trigger + generic outbound webhook** (`outbound_webhooks`, `webhook_deliveries`, pg_net). AFTER INSERT on `sales` posts `sale.created` (sale + customer + journey snapshot) to every active hook, with header `X-Trax-Webhook-Secret`. A failure never blocks the insert; it is logged. Managed in Settings > "וואטסאפ וסוכן AI".
2. **n8n orchestrates, the Edge Function `cloudchat-bridge` decides.** n8n `TRAX - WhatsApp ליד חדש` (aZ475pR5nxSdzhuU) receives the hook, waits 60 s (lead intake PATCHes the auto-created sale after the INSERT), then calls `cloudchat-bridge {action:'send', sale_id}`. All rules and all writes are in the function, in the repo: checkbox, TRAX only, opt-out, dedupe per customer, test mode, template lookup, send via `send-whatsapp-template-by-user-id`, write-back of user_ns, chat link, status and stage `ליד חדש` -> `נוצר קשר על ידי AI`, plus `crm_customer_id`/`crm_sale_id` subscriber fields in CloudChat so Max knows which records to update.
3. **Reply detection by polling**, not by repointing the bot's webhook fields (they belong to the platform; repointing them would cut Max off). n8n `TRAX - WhatsApp סנכרון מענה וסטטוס` (lo7rijctoKVu3DwV) calls `{action:'sync'}` every 5 minutes: an inbound row after the send = `ענה לסוכן`; a Meta error row = `השליחה נכשלה`; "הסר"/"stop" = `whatsapp_opt_out`; no answer after N hours = one call task for the owner.
4. **Read-only chat panel** through `{action:'chat'}` with the user's JWT; the record is read under the caller's RLS and the CloudChat key never reaches the browser.
5. **Hand-off:** Max PATCHes the sale through api-v1 (`stage: 'שיחת מכירה עם נציג אנושי'`, `qualification_rating`, `qualification_summary`); trigger `sales_ai_handoff` opens a high-priority call task and notifies the owner, once per sale.
6. **Test mode until Sahar says go live** (`system_settings.whatsapp_test_mode`, phones in `whatsapp_test_phones`): staging and production share this DB, so every real lead fires the hook; in test mode the function skips anyone not on the list.

**Why not the alternatives:** an n8n-only flow would put the rules in an unversioned JSON on a shared server; the automation engine's `create_record` maps `related_type` to the table name (`sales`), which `tasks_related_type_check` rejects, so it was not reused for the tasks here. Statuses: empty = not sent, `נשלחה הודעה`, `ענה לסוכן`, `השליחה נכשלה` (sale level, Sahar's choice).
